### P1-2 隐私弹窗授权链不闭环 + 事件双触发
- 组件：`miniprogram/components/privacy-popup/privacy-popup.wxml:8` 的"同意并继续"同时写了 `open-type="agreePrivacyAuthorization"`、`bindagreeprivacyauthorization="accept"` 和 `bindtap="accept"` → `accept` 会被触发两次（`privacy-popup.js:6-10`：双写 storage、双 triggerEvent，当前无崩溃但属错误用法）。
- 全工程检索：**无** `wx.onNeedPrivacyAuthorization`、`wx.requirePrivacyAuthorize`、`wx.getPrivacySetting`、`wx.openPrivacyContract`（0 命中）。即弹窗只把 `privacyAccepted` 写进本地 Storage（`privacy-popup.js:7`），与微信隐私授权链路没有连接。
- 触发面：弹窗只在首页 `pages/home/home.wxml:18` 渲染；分享卡片直接进入 `pages/case-detail/case-detail?id=...`（`case-detail.js:51` 自己生成该分享路径）时不会弹窗，`privacyAccepted` 可能长期为 false。
- 当前发布路径未调用任何微信隐私接口（见 2.2），所以**不会因此崩溃或触发线上报错**；但若后续启用隐私接口，或审核员按"隐私弹窗"标准检查，授权链不闭环属于高风险。
- 修复建议（二选一，推荐 a）：
  a) 本版明确无隐私接口 → 移除 `open-type`/`bindagreeprivacyauthorization` 与重复绑定，弹窗只做"隐私说明 + 去隐私页"提示（保留本地 dismissed 标记即可）；
  b) 若坚持微信授权弹窗 → 按官方 `wx.onNeedPrivacyAuthorization(resolve => ...)` + 按钮 `id` + `resolve({ buttonId, event: 'agree' })` 接入（官方文档：https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html ，正文为前端渲染，我未能抓取正文，规则以官方原文为准【未验证】）。

### P1-3 benchmarkLevel 字段归属待核实，低端机降级策略可能永不生效
- `miniprogram/app.js:13`：`device.benchmarkLevel > 0 && device.benchmarkLevel < 12` 决定 `reducedMotion`；
- `miniprogram/components/space-scene/space-scene.js:39`：`device.benchmarkLevel > 0 && device.benchmarkLevel < 8` 决定是否直接走 2D fallback；
- `space-scene.js:65`：`Number(device.benchmarkLevel || 0) >= 15` 决定 WebGL antialias。
- 三处都从 `wx.getDeviceInfo()` 取值；但微信新系统信息 API 已拆出独立的 `wx.getDeviceBenchmarkInfo`（官方文档侧栏可见），`benchmarkLevel` 传统上只在该接口/旧 getSystemInfoSync 返回，且**仅 Android 有效、不可用时为 -1**。若 `getDeviceInfo()` 不返回该字段：`reducedMotion` 恒 false、低端机降级永不触发、antialias 恒关。
- 证据：代码位置已确认；官方文档正文为前端渲染，我未能抓取字段表，故字段归属**【未验证】**。
- 修复/验证：在开发者工具 console 与一台 Android 真机分别打印 `wx.getDeviceInfo()`、`wx.getDeviceBenchmarkInfo()` 对比；若字段不在前者，改为 `wx.getDeviceBenchmarkInfo()`（try/catch 兜底），并保留 -1/undefined 的保守分支。
