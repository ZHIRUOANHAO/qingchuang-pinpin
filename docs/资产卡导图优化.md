# 资产卡导图优化

## 范围

将原本平铺的阶段入口和文字列表改为可沿导线阅读的层级结构，不新增后台、编辑器、自由拖拽、公开评论或内容生成。

- 案例根节点 → 七阶段资产卡：点击打开对应阶段。
- 阶段根节点 → 目标、做法、适用赛道、资产类别、成本、风险与复用信息。
- 资产类别 → 实际资产条目；空类别不显示，不填造假内容。

连线表示资产归属与阅读层级，不表示因果证明或收益保证。原案例正文、来源说明、DNA 交互和画布流程保留。

## 实现

- `miniprogram/utils/asset-map.js`：原生与网页共用同一份纯视图模型，不修改原始案例。
- `miniprogram/components/asset-map/`：原生资产导图。主干、分支、卡内子线均与卡片共同布局，文字换行、滚动时不依赖固定屏幕坐标。
- `miniprogram/pages/case-detail/`：接入案例与七阶段导图，保留原节点选择、详情阅读遮罩。
- `miniprogram/components/node-detail-sheet/`：接入阶段内资产导图，保存失败不再显示成功；保存和关闭仍可用。
- `preview/asset-map.js`、`preview/app.js`、`preview/styles.css`：网页同步，手机纵向展开，桌面根节点与分支分列。

样式沿用深蓝底、暖金主节点、青色导线。静态分支不伪装成按钮，可交互卡片保持足够触控面积。未新增动画，因此不会给减少动态用户额外负担。

## 分工说明

总控负责数据模型、原生案例页接线和统一验收；`native_asset_map` 协作代理负责原生组件与详情页；`web_asset_map` 协作代理负责网页实现。测试代理未完成的部分由总控补齐。

本轮分工发生在本会话协作代理中；无项目聊天窗口发送工具，未实际发布到侧栏其他聊天窗口。
