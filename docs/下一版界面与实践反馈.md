# 下一版界面与实践反馈

用户已选择：下一版先做可体验预览，当前备案版本保持稳定；以实践记录（做法、结果、证据）为主，附普通问题与评论。本轮入口与代码独立放在 `preview/practice-feedback/`，未接入原生小程序的正式发布路径。

用户本轮追加：案例库专业化内容太多，需要生活化、通俗易懂的入门入口。当前公开摘要实际统计：100 条中 80 条有“海外业务样本”标签，59 条有“技能试做”标签，9 条有“轻量试做”标签；少启动现金不等于低理解门槛。

## 生活化入口

第一屏增加三个情境练习，明确“非经营实证”，不计入原有 100 条案例数。先呈现身边的需要、一页最小交付与今天第一步，再引向进阶案例。

| 情境练习 | 可让别人试用的小交付 | 现库工具参考 |
| --- | --- | --- |
| 给身边小店做价目表 | 一张信息清楚的价目表样稿 | real_092 创客贴 |
| 把同学的简历排清楚 | 一页层次清楚的简历样稿 | real_020 五百丁 |
| 给活动整理报名信息 | 一张能收齐必要报名信息的表格 | real_015 Tally |

这些练习是参考工具能力设计的任务。工具公司出售会员功能，与个人替别人做一张表或排一页文字，是不同的服务与交易链路；不能据工具公司存在认定练习已有人付费，不能用完成练习证明原企业的经营效果。

练习草稿保存独立来源元信息 `exerciseId`、`exerciseTitle`，恢复编辑与复制摘要后仍能识别来源。实践结果、行动和证据由使用者实际填写，不自动填入“做过”“成功”或收益数据。下一步应观察新用户能否说清需要者、交付物和第一动作，再收集真实试用反馈。

## 用户路径与界面

`搜索真实案例 → 看懂卖什么、谁使用/付款 → 查看阶段与来源 → 记录自己的实践 → 保存本机草稿 → 复制摘要分享/带回后续核对`

- 保留深蓝、金色和 DNA 阶段标识，减少阅读区的装饰噪声。
- 列表先呈现案例用途、买家与来源，完整正文按需读取。
- 案例详情并列呈现原案例来源、公开实践反馈、本机草稿；三者不能互相冒充。
- 实践记录字段：时间、实际条件、做法、结果类型、具体结果、证据描述、可选公开 HTTPS 链接、补充评论。
- 结果允许顺利、部分有效、失败、暂不确定；失败记录可与正向记录使用同样的展示机会。
- 普通问题/评论有独立类型，不能被计为一次实践验证。

当前公开实践区为空，不预置真实用户身份、成功次数、收入或“已验证”数字。本机草稿不会对其他人可见。删除与复制摘要都是作者主动操作；草稿的本地存储失败必须明确报错，不能显示成功。

## 证据分层

| 信息 | 能说明什么 | 不能自动推导什么 |
| --- | --- | --- |
| 原案例公开来源 | 某日期能核对到产品、服务与官方说明 | 已审计成交、净利润、普通人可复制 |
| 用户实践自述 | 作者声称在具体条件下做过什么、观察到什么 | 已独立核验，或整条案例有效 |
| 后续证据核对记录 | 哪份材料在何时由谁核对，支持哪个具体事实 | 所有陈述都真实、未来结果有保证 |

内容安全接口只判断违规风险。即使内容检测通过，也不能自动给投稿加“收益已验证”或“案例已经有人证明有效”的标签。

## 后续公开发布方案

目标路径：`提交实践记录 → 内容安全检测 → 人工检查内容/证据 → 作者确认公开脱敏版本 → 展示 → 支持撤回和举报`。

公开版本需要可信的服务端作者身份、权限隔离、审核状态、编辑后重审、删除及举报处理。初期先人工审核后展示是本项目建议的实现方式，不能把前端草稿状态直接当作发布状态。

当前为个人主体，需要核对后台实际服务类目。微信官方个人类目“工具—备忘录”明确不覆盖用户原创内容的传播与公开访问，“工具—记账”也不覆盖自定义内容记录分享；不能因把评论改名为反馈就视为范围不变。其他工具类目的附属案例反馈是否适用，仍需依据真实类目及完整交互向平台确认。官方依据：[服务类目表](https://developers.weixin.qq.com/miniprogram/product/material/)。

文本检测使用服务端 [msgSecCheck](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_msgseccheck.html) 的 `version: 2`、评论场景 `scene: 2`；必须检查 `result.suggest`，不能只检查 `errcode: 0`。图片若后续开放，使用 [mediaCheckAsync](https://developers.weixin.qq.com/miniprogram/dev/server/API/sec-center/sec-check/api_mediacheckasync.html)，等有效事件回调再处理；首次返回的 `trace_id` 不代表通过。回调接收方式须按 [消息推送文档](https://developers.weixin.qq.com/miniprogram/dev/framework/server-ability/message-push) 核验，不能假设普通云函数可接全部推送。

公开前需更新实际数据流、信息保存和删除渠道，按 [隐私指引](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/miniprogram-intro.html) 处理公开内容及用户同意；截图应去掉客户姓名、手机号、地址、账号等不必要信息。投诉与运营责任以 [平台运营规范](https://developers.weixin.qq.com/miniprogram/product/) 为准；不要完全依赖自动检测，参见 [健康运营指引](https://developers.weixin.qq.com/miniprogram/dev/framework/operation.html)。

## 打开预览

项目根目录双击 `start-practice-feedback-preview.cmd`。脚本复用现有本地服务器并核对页面，默认地址 `http://127.0.0.1:4173/preview/practice-feedback/`；端口占用时可能选用相邻端口，以启动输出为准。

草稿只存浏览器当前站点的 `qingchuang:practice-feedback:v1`，不读取或改动当前小程序的收藏、画布和验证记录。不承诺在微信、其他浏览器或其他设备间同步。此入口是网页交互预览，不代表原生小程序已编译、公开评论已上线或备案已通过。
