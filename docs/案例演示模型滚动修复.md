# 案例演示模型滚动修复

用户确认的问题：上下滚动页面时，文字移动，但模型停在屏幕原位或漂移。

## 复现与原因

微信开发者工具中已复现。原案例演示页将整页内容放在 `height:100vh` 的 `scroll-view` 中，内嵌 WebGL Canvas。滚动时 DOM 容器坐标更新，但模型的原生画面没有同步，覆盖了下方评分、图例及操作按钮。

模型原本已有固定高度的局部容器（`50vh`、最小 320px、最大 430px），并非没有容器，也没有在源码中设为 `position:fixed`。本次故障来自该页滚动结构与原生 Canvas 画面的配合。

## 修改

- `miniprogram/pages/ai/ai.wxml`：移除整页 `scroll-view`，与案例详情、画布一致使用页面滚动；模型仍处于原有局部容器，随页面移动。
- 原有模型尺寸、旋转、缩放、节点详情及首页星球代码保持原样。
- 修改前文件已复制到 `output/backups/dna-scroll-before-2026-10-26/ai.wxml`，并核对 SHA256 一致。

## 实测

同一设备尺寸、同一案例，在滚动前后各截图一次：

| 检查 | 修复前 | 修复后 |
| --- | --- | --- |
| 页面与 Canvas DOM 坐标位移 | 150.40 CSS 像素 | 150.40 CSS 像素 |
| 模型画面实际位移 | 约 0.07 截图像素，几乎未动 | 188.16 截图像素 |
| 按截图缩放换算的预期位移 | 188.41 截图像素 | 188.41 截图像素 |
| 模型是否随所属区域移动 | 失败 | 通过 |

原有 DOM 几何检查在修复前也能通过，因此新增脚本会识别截图中球体的大块连通颜色区域，检查模型画面位移，避免只检查容器位置就误判成功。小图例和文字不计入球体像素。

- 原生界面回归 20 项通过，包含纵向手势交给页面、横向手势旋转模型及首页交互边界。
- 体验逻辑回归 15 项通过。
- 实际模拟器节点阅读遮罩可打开、关闭，Canvas 隐藏与恢复均通过。
- Git 空白检查通过，仅有已有的 LF/CRLF 转换提示。

截图与结果在 `output/playwright/dna-scroll-2026-10-26/`：`before-scroll-a.png`、`before-scroll-b.png`、`after-scroll-a.png`、`after-scroll-b.png`，以及两份 `*-result.json`。

## 重复检查

辅助工具为 `scripts/check-native-dna-scroll.cjs`。需要微信开发者工具打开本工程、启动本地自动化连接，并在项目临时工具目录安装测试用 SDK：

```powershell
npm install --prefix output/wx-automation --cache output/wx-automation/npm-cache --no-audit --no-fund --package-lock=false miniprogram-automator@0.13.0
& 'D:\应用\微信web开发者工具\cli.bat' auto --project 'D:\UserFolders\Desktop\qingchuang-pinpin' --auto-port 9521 --trust-project --lang zh
node scripts/check-native-dna-scroll.cjs after
```

SDK 及其依赖仅放在已忽略的本机 `output/` 中，不进入小程序依赖或发布包。脚本只操作本地模拟器中的页面、截图及临时显示状态，不上传代码，不保存用户业务记录。

## 分工与交付边界

`dna_scroll_diagnosis` 子代理只读诊断布局和最小方案；总控负责原生模拟器复现、源码修改、截图像素比较与回归验收。没有项目聊天窗口发送工具，未实际向其他侧栏窗口发布任务。

本轮修复仅在本地开发工程，未修改微信平台上的审核包或线上版本。微信开发者工具实测通过；iOS、Android 手机仍需扫码复验。应用版本号仍沿用此前文件中的 `0.1.0`，本次没有另行改号或宣称已发布 `0.2.0`。
