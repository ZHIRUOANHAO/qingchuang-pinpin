# 发布配置与未启用服务说明

## 当前发布版无需 API

当前版本是纯本地预置案例库，运行时不调用外部 API、微信云函数、云数据库、云存储、微信支付或广告接口。因此正式发布不需要 AI 密钥、云环境 ID、支付商户号、产品价格表或广告单元 ID，也不需要为这些历史能力配置合法域名。

`miniprogram/config/env.js` 的当前发布约束为：

```js
{
  runtimeMode: 'local_case_library',
  cloudEnabled: false,
  cloudEnvId: '',
  privacyPolicyVersion: '1.0',
  supportEmail: '',
  supportEmailRequiredBeforeRelease: true,
}
```

其中 `supportEmail` 必须在提交审核前替换为发布主体真实可用的联系邮箱。不要用示例邮箱绕过预检。

## 广告配置

`miniprogram/config/ads.js` 必须保持：

- 总开关为 `false`。
- 所有广告单元 ID 为空。
- 案例阅读、案例演示、画布和法律页不出现广告解锁或激励入口。

## 历史脚手架

`cloudfunctions/` 以及登录、用户资料、AI、订单和支付服务文件是历史研发脚手架。它们不属于当前发布路径：

- 不部署云函数。
- 不创建 `users`、`orders` 等集合。
- 不配置 DeepSeek、Anthropic 或其他模型密钥。
- 不配置支付产品、商户号或回调。
- 不在审核说明中申报这些未启用能力。

保留文件只用于追溯旧方案，不代表产品当前收集数据、提供生成服务或具备交易功能。

## 恢复在线能力的门槛

若未来恢复 AI、上传、云登录、支付或广告，应作为独立版本重新立项，并至少完成：

1. 重新确认主体、服务类目与平台准入条件。
2. 更新隐私保护指引、用户协议、数据清单和未成年人保护说明。
3. 明确数据流向、保存期限、删除机制、内容安全与投诉流程。
4. 服务端托管密钥，增加鉴权、限流、日志脱敏和成本控制。
5. 完成专项自动化测试、微信开发者工具编译、真机与审核验收。

## 发布检查

运行：

```powershell
npm.cmd run check:release
```

只有正式 AppID、真实支持邮箱以及其他代码检查全部通过后，才进入上传步骤。备案、服务类目、后台隐私配置和真机验收仍需人工完成，不能由脚本替代。
