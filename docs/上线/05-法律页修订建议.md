# 05 法律页修订建议

> 使用方式：真实主体/邮箱/备案号到位后，按本文件逐条替换；不要先写占位假值，也不要保留"待配置"类文案。
> 本文件所有替换均以【】标注待填值；任何未提供的值保持空缺，宁可不写也不编造。

## 0. 修订原则

1. 主体、邮箱、备案号、版本、日期五类信息是审核重点；缺一项就可能被判"信息不完整"。
2. 页面不出现开发者自检警告或"待配置"文案（历史教训见 docs/上架问题清单.md:42；2026-09-27 上架核查记录:26-32）。
3. 三份法律页 + 关于页 + 后台隐私指引的版本/日期/口径必须一致。
4. 改完必须跑发布预检与结构测试，不能只看页面。
5. 本文件不修改源码；以下"建议替换"由源码负责人执行，建议由同一人一次性完成，避免多处日期不一致。

## 1. 建议的信息源集中化

现状：版本在 env.js:5；日期硬编码在三个页面的 js（privacy.js:12、agreement.js:9、minors.js:1）；邮箱在 env.js:6。
建议：在 miniprogram/config/env.js 增加主体与备案字段，让页面统一从 env 读取，避免四处手改（示例字段名可调整）：

    const env = {
      runtimeMode: 'local_case_library',
      cloudEnabled: false,
      cloudEnvId: '',
      privacyPolicyVersion: '1.1',
      legalUpdatedAt: '【YYYY-MM-DD】',
      subjectType: '【个人/企业】',
      subjectName: '【主体全称】',
      filingNo: '【备案号，未取得则留空】',
      supportEmail: '【真实邮箱】',
      supportEmailRequiredBeforeRelease: true,
      serviceHotline: '【客服电话或留空】'
    }

注意：env.js 属于 miniprogram/ 源码，本任务不修改；由源码负责人执行，并同步更新 01 的字段表。

### 2.9 miniprogram/app.js（官方隐私授权接入建议）

现状：onLaunch 只做设备信息与本地 privacyAccepted 读取（app.js:10-15）。
建议（伪代码，需源码负责人实现并真机验证）：

    onLaunch() {
      // 保留现有设备信息读取
      if (wx.onNeedPrivacyAuthorization) {
        wx.onNeedPrivacyAuthorization(resolve => {
          // 展示 privacy-popup，用户同意后：
          // resolve({ event: 'agree', buttonId: 'agree-btn' })
          // 用户拒绝：resolve({ event: 'disagree' })
        })
      }
    }

注意：
- 不应在用户未同意前调用隐私接口；wx.requirePrivacyAuthorize 可用于"先授权后执行复制"。
- 自建弹窗与官方弹窗不能重复骚扰；若接管了 onNeedPrivacyAuthorization，官方默认弹窗不再出现（以真机验证为准）。
- app.json:44 已注册 privacy-popup；首页 home.js:15 的显示逻辑应改为由授权状态驱动，而不是仅看本地标记。

## 3. 修订顺序（建议）

1. 用户提供真实值（主体、邮箱、备案号、生效日期、客服方式）。
2. env.js 加字段并填值（01 第 2 节字段 11-16）。
3. privacy.js / agreement.js / minors.js 的日期与版本读 env。
4. privacy.wxml 第 01/07 节、agreement.wxml 第 07 节、minors.wxml 第 07 节、about.wxml 全部替换。
5. privacy-popup 文案与官方授权逻辑（可与第 4 步并行，但需真机验证）。
6. 运行校验（第 5 节），更新文档版本记录（docs/上线/01 的字段表状态）。

## 4. 版本与日期策略

- 隐私保护指引：回填后升 1.1；后台版本号与页面版本号一致；生效日期用实际上线/更新日。
- 用户协议：同步 1.1；日期一致。
- 未成年人保护说明：同步版本；日期一致。
- 关于页版本：与开发者工具上传版本一致（建议 1.0.0），不要再用"0.1.0 / 本地案例版"这种"本地版"字样（审核员看到会认为不是正式版）。
- 未来任何功能变化（新增 AI/上传/登录/支付/广告）：必须先升版、改隐私指引、重新取得同意，再上线。

## 5. 修订后校验

命令（项目根目录）：

    npm.cmd run check:release
    node -e "const {env}=require('./miniprogram/config/env.js');console.log(JSON.stringify(env,null,2))"
    Select-String -Path miniprogram/pages/privacy/privacy.js,miniprogram/pages/agreement/agreement.js,miniprogram/pages/minors/minors.js -Pattern 'updatedAt'

人工检查：

- 三份法律页 + 关于页的版本/日期/主体/邮箱是否一致。
- 页面是否还残留"待配置/待确认/上线前补充"类文案。
- 后台隐私指引的协议名称/版本/日期与页面是否一致。
- 首页隐私弹窗与官方授权流程是否重复弹窗（真机）。
- 断网下法律页是否可正常打开。
