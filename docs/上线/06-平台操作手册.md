## 1. 公众平台侧一次性设置（mp.weixin.qq.com）

按顺序完成，全部在“小程序后台”内：

1. **账号信息**：设置 → 基本设置
   - 小程序名称、头像、简介、服务类目、服务标签。
   - 名称/头像/简介三者必须互相关联且与实际功能一致；简介要写出功能点，不能是“提升生活品味”这类模糊表述（官方《常见拒绝情形》1.1/1.2）。
   - 头像需清晰、可用白底但要有色边框，不得含腾讯/微信官方元素。
2. **用户隐私保护指引**：设置 → 基本设置 → 服务内容声明（入口名称以后台为准）→ 用户隐私保护指引
   - 官方填写说明：[用户隐私保护指引填写说明](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)（2026-10-22 可访问；正文因页面过长未能逐字抓取【需核实】）。
   - 本版实际处理：本机缓存（收藏/画布/方案/隐私同意标记）、启动时读设备性能等级与窗口信息（不保存）。**不要勾选**位置、相册、通讯录、手机号、上传文件等本版不用的能力。
   - 后台指引版本号/更新日期要与小程序内 `privacyPolicyVersion` 保持一致（当前 `env.js` 为 `1.0`）。
3. **成员与体验成员**：用户身份 → 成员管理
   - 个人主体上限：项目成员 15、体验成员 15（官方客服文档《小程序成员管理》，2026-10-22）。
   - 建议：管理员 1 + 开发 1 + 运营 1；体验成员按 iOS/Android 真机各至少 1 人。
4. **开发设置**：开发管理 → 开发设置
   - 本版**不需要**配置服务器域名、业务域名、uploadFile/downloadFile 合法域名（无网络请求）。
   - AppID 与 `project.config.json` 必须一致；建议在此页面截图留档“AppID + 主体名称”。
5. **备案信息**：设置 → 小程序备案
   - 官方指引：备案通过后，**小程序备案号会在小程序发布上线后自动展示在“更多资料”页，无需开发者自行悬挂**（[微信小程序备案操作指引](https://developers.weixin.qq.com/miniprogram/product/record/guidelines)，2026-10-22）。
   - 但仍建议在“关于”页写明主体名称与备案号（用户可核对、审核员可核对）；**备案号必须等用户提供后才能写，不得编造**。
6. **审核素材准备**（提审时用）：见第 4 节与 `08-模拟审核预检.md`。

## 2. 微信开发者工具：编译与上传

### 2.1 导入与基础检查

1. 打开开发者工具 → 导入项目 → 目录选**项目根目录**（含 `project.config.json`，不是 `miniprogram/`、也不是 `preview/`）。
2. 确认右上角 AppID 显示 `wx031b9c2a3d1d73bb`，项目名 `qingchuang-pinpin`。
3. 详情 → 本地设置：确认“不校验合法域名”**不需要**勾选（本版无请求；勾选反而掩盖问题）。
4. 工具 → 构建 npm（项目依赖 `threejs-miniprogram` 等需要构建产物）。
5. 清缓存（工具 → 清除缓存 → 全部清除）后重新编译一次，避免旧缓存造成“本地能跑、上传后白屏”。

### 2.2 提交上传前的 60 秒自检（必须做）

- [ ] 控制台无红色报错、无“隐私接口未声明”提示。
- [ ] 五个 Tab（星球/案例/案例演示/画布/我的）逐一点开，无白屏、无 undefined。
- [ ] 断电断网（关闭 Wi-Fi + 流量）后重进：预置案例仍可看；不出现 AI/上传/登录/支付相关报错。
- [ ] 从首页 → 案例详情 → 装配到画布 → 生成验证方案 全链路走通。
- [ ] 隐私保护指引、用户协议、未成年人保护三页可打开，内容与实际功能一致。
- [ ] 版本号、关于页版本号、后台版本号三者计划一致（当前 `pages/about/about.wxml` 显示 “0.1.0 / 本地案例版”，提审前要改成与上传版本一致，例如 1.0.0）。

### 2.3 点“上传”

1. 工具栏右上角 **上传**。
2. 版本号：首次正式提审建议 **`1.0.0`**（语义化：主.次.修订；后续修复递增修订号，功能变化递增次版本号。微信后台对格式的强制校验以后台提示为准【需核实】）。
3. 项目备注：会展示给审核人员，**不要留空**。模板：
   ```
   版本 1.0.0：100 条公开商业案例的结构化学习；全部预置在包内，无需登录/上传/支付；无外部请求；无广告。
   本次变更：正式主体信息与联系方式回填；基础库版本统一。
   ```
4. 上传成功后，在开发者工具“版本管理”或公众平台“开发管理 → 开发版本”确认出现 `1.0.0`。

### 2.4 上传后立刻做的两件事

- **设为体验版**：公众平台 → 开发管理 → 开发版本 → 选 `1.0.0` → 设为体验版 → 生成二维码。
- **加体验成员**：成员管理里把 iOS/Android 各至少 1 台真机的主人加为体验成员，扫码走完整流程并截图留证（审核被拒时这些截图是申诉材料）。

## 3. 提交审核（版本管理 → 提交审核）

1. 公众平台 → 管理 → **版本管理** → “开发版本”中选中 `1.0.0` → **提交审核**。
2. 填写审核信息（逐项，别嫌繁琐）：
   - **服务类目**：与第 1 节所选一致；类目对应功能必须能在首页直达或 2 次点击内到达（官方《常见拒绝情形》3.1.2）。
   - **功能页面/测试路径**：列出审核员最该走的 5 条路径 + 直达链接（见下方模板）。
   - **测试账号**：本版无账号体系 → 勾选/填写“无需登录即可体验全部功能”（官方要求：若存在账号体系必须提供可体验全部功能的测试号，3.3.4）。
   - **隐私保护指引**：确认已配置且与页面一致。
   - **截图**：按 08 文档的“审核截图清单”准备，截图必须与实际页面一致，不得 P 图/加字。
3. 审核说明模板（可直接粘贴，按实际修改）：

```
【产品定位】商业案例结构化学习工具。100 条案例全部免费，内容随安装包预置。
【无以下能力】无生成式 AI、无文件/图片/网址上传、无云登录、无会员/订单/支付、无广告、无海报生成、无用户发布内容。
【无需登录】打开即用全部功能；本机收藏/画布/方案仅存于当前设备，可在“隐私与权限”页一键清除。
【测试路径】
1) 首页：隐私提示 → 同意并继续 → 拖动星球 → 点任意案例
2) 案例页：搜索“咖啡” → 筛选 → 打开详情 → 查看公开证据链接 → 收藏
3) 案例演示：选择一个内置案例 → 载入 DNA → 查看七阶段资产卡
4) 画布：添加模块 → 查看实时验算 → 保存方案 → 生成验证方案
5) 我的：隐私与权限 → 用户协议 → 未成年人保护 → 关于（含主体信息）
【内容边界】案例仅作结构化学习，不构成收益承诺或投资建议；案例来源、证据边界与风险提示在详情页可见。
```
4. 提交后状态：`审核中` → `审核通过` / `审核不通过`。审核期间**不要重复提交新版本**；确需修改先撤回（版本管理 → 撤回审核）再重新上传。

## 4. 审核时长、加急与催审

| 事项 | 事实 | 来源 |
|---|---|---|
| 常规审核时长 | 官方**没有**公开承诺固定时长；社区经验通常 1–7 个工作日，首次提审/类目敏感时更长 | 【社区经验，非官方承诺】 |
| 普通开发者自助加急 | 公众平台**未对普通开发者开放**通用的“加急审核”按钮；是否存在临时活动额度以后台为准 | 【需核实】 |
| 服务商加急能力 | 开放平台第三方 API 有“加急代码审核”，官方描述“加急后预计 2-12 小时内审完，复杂逻辑可能延长” | [加急代码审核](https://developers.weixin.qq.com/doc/oplatform/openApi/miniprogram-management/code-management/api_speedupcodeaudit.html)（2026-10-22） |
| 催审渠道 | 微信开放社区“小程序”板块发帖（附 AppID、提审时间、版本号）；腾讯客服；审核结果页反馈 | 官方社区/客服（具体入口以当时页面为准【需核实】） |
| 催审不要做的事 | 不要连发多个同名版本、不要用无关类目“借道”提审、不要在备注里写“求加急/急上线”施压 | 运营规范与社区经验 |

> 建议排期：**提审前预留 3 个工作日 + 1 轮被拒修改时间**。被拒后修改 + 重新提审通常要再等一轮，不要按“当天过”做上线计划。

## 5. 被拒后的处理（修改 → 重新提审 / 申诉）

1. **看懂拒绝原因**：版本管理 → 审核不通过 → 查看“拒绝原因”；同时看站内信/模板消息/服务通知。
2. **归类**：
   - 资料类（名称/头像/简介/类目/备案/隐私指引）→ 后台改，不用重新上传代码；
   - 代码/内容类（页面内容、功能缺失、文案敏感）→ 改代码 → 重新构建 → 递增版本号 → 重新上传 → 再提审；
   - 误判类（审核员没看到入口/测试路径不清）→ 先补“审核说明 + 截图 + 测试路径”，再申诉。
3. **申诉**：审核结果页一般提供“申诉”入口；也可在微信开放社区按模板发帖（附 AppID、版本号、提审时间、拒绝截图、整改说明、真机截图）。申诉要**逐条对应拒绝理由**，不要只写“已修改请复审”。
4. **重新提审规范**：版本号必须递增（如 1.0.0 → 1.0.1），备注写清“针对拒绝原因 X 的整改点”，便于审核员对照。
5. **被拒沟通模板**：

```
拒绝原因：XXX（原文）
整改说明：
1) 已删除/修改 XXX，位置：页面「我的 → 关于」第 X 段；截图见附件 1。
2) 已在审核说明补充测试路径：首页 → …… → 第 3 步即可看到 XXX。
3) 复测设备：iPhone（微信版本 X）/ Android（微信版本 X），录屏见附件 2。
本次版本号 1.0.1，未新增任何交易/上传/AI 能力。请复核。
```

## 6. 发布（审核通过后）

1. 公众平台 → 版本管理 → 审核版本（已通过）→ **提交发布**。
2. 发布模式（官方《小程序分阶段发布功能介绍》，2026-10-22）：
   - **全量发布**：立即向全部用户发布；
   - **分阶段发布**：15 天内按自定义比例逐步放量；可提升比例、可撤销；
   - **第一个版本必须选择“全量发布”**（本项目即首个版本）；
   - 存在分阶段发布中的版本时，不可发布新版本、不可回退已全量发布的线上版本；
   - 15 天内未主动撤销/全量，平台会在第 15 天自动全量发布；
   - 撤销分阶段发布后，所有用户回到上一个全量发布的线上版本。
3. 发布后立刻确认：
   - 微信里搜索小程序名称可进入；
   - 线上版本号与审核通过的版本一致；
   - “更多资料”页能看到备案号（官方：上线后自动展示，见 0.2 来源）；
   - 分享给好友的卡片标题/路径正常。

## 7. 版本回退（线上出问题时）

1. 公众平台 → 版本管理 → 线上版本 → **版本回退**，选择要回退到的历史版本。
2. 已知限制（官方分阶段发布说明 + 开放平台“小程序版本回退”能力，2026-10-22）：
   - 只能回退到**上一个全量发布**的版本；
   - 若上一版本是“分阶段发布且已撤销”，当前线上版本**不可回退**；
   - 回退是运营动作，不是“撤回审核”；回退后仍需重新上传修复版本并走审核。
3. 本项目应急预案：
   - 首个版本无历史版本可回退 → **首版上线后 7 天内不做大改**，任何改动先走体验版；
   - 线上白屏/崩溃级问题：先“暂停服务”（设置 → 基本设置 → 暂停服务）止损，再修复提审；恢复需重新开启并告知用户。

## 8. 上线后 24 小时 / 7 天检查

- 24h：搜索可搜到、分享可用、5 个 Tab 无报错、后台“运维中心”无 JS 错误激增、用户反馈渠道可用。
- 72h：“更多资料”页备案号正常；微信“小程序数据助手”看到访问；无隐私/内容类投诉。
- 7d：整理首轮反馈（见 07 第 F 组“用户反馈入口”），确定 1.0.1 修复清单；不急于加功能。

## 9. 高频操作错误（每一条都真实发生过）

1. 上传的是测试 AppID（`wx2f9d25ee643ab824`）→ 审核无法关联正式主体。当前仓库已改为正式 AppID，但**上传前仍要在工具右上角再确认一次**。
2. 忘记“构建 npm” → 上传包缺依赖，审核员打开即报错。
3. 版本号与上次重复 → 上传/提审被拦截或覆盖混乱。每次提审必须递增。
4. 项目备注留空或只写“修复 bug” → 审核员缺少上下文，容易被拒。
5. 后台隐私保护指引没配，代码里却弹隐私提示 → 两边不一致，按 3.4 用户隐私条款质疑。
6. 类目选“教育服务”但无资质 → 直接拒；案例学习不要申报教育培训。
7. 截图用浏览器预览图而非真机截图 → 与线上不一致，拒。
8. 分阶段发布期间又发布新版本 → 被系统禁止，白忙一场。
9. 首版就想灰度 → 官方要求第一个版本必须全量发布。
10. 把 `preview/` 当小程序上传 → 目录选错，上传失败或内容不符。
